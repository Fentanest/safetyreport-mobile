## A. 이슈 12번 — 공식 사이트 목록 조회가 401(“로그인이 만료되었습니다”) **[긴급, 모든 Standalone 사용자]**

### 확인된 사실 (2026-10-23, 검수자가 205 PC 서버 안에서 사용자 본인 계정으로 실측)
같은 토큰으로 `GET https://www.safetyreport.go.kr/api/v1/portal/mypage/mysafereport?startRowNum=1&endRowNum=1&…` 비교:

| 요청 | 결과 |
|---|---|
| PC 방식(curl_cffi, 토큰 + 쿠키 JSESSIONID·WMONID) | 200 |
| PC 연결 방식, 쿠키 없음 | 401 |
| 모바일 헤더(Android UA·Referer·X-Requested-With) + 쿠키 | 200 |
| 모바일과 똑같이(토큰만, 쿠키 없음) — v2.0.0~2.5.1 모바일 방식 | **401** |
| `JSESSIONID` 만 | 200 |
| `WMONID` 만 | 401 |
| 가짜 `JSESSIONID` | 401 |
| 상세 `…/mysafereport/{C_NO}` 쿠키 없음 / 있음 | 200 / 200 |

→ 공식 사이트가 이제 **목록 조회에 로그인 세션의 진짜 `JSESSIONID` 를 요구**한다. 헤더·TLS·UA 는 무관하다.
모바일은 로그인 때 RSA 공개키 응답의 `JSESSIONID` 를 토큰 발급 요청에만 쓰고(`standalone_auth_service.dart` 200–260행), 목록 등 API 요청에는 보내지 않는다(`standalone_api_service.dart` 119·187·229행). 재로그인 후 재시도도 401 → `TokenExpiredException` 기본 문구.
PC(`core/crawler/direct_login.py` 138–145·227–237행)는 `JSESSIONID`·`WMONID` 를 저장해 모든 API 요청에 보낸다 — PC·Client 모드는 영향 없음.

### 고칠 것
1. 로그인할 때 받은 `JSESSIONID`(RSA 키 응답, 그리고 토큰 응답에 `Set-Cookie` 로 새 값이 오면 그 값)와 `WMONID`(있으면)를 토큰과 **같은 보안 저장소·같은 계정 범위·같은 수명**으로 저장한다.
2. 공식 사이트에 `Authorization` 을 붙이는 **모든 요청**(목록·상세·만족도·보완·사진 등 — `StandaloneApiService` 와 다른 서비스 전부 찾기)에 `Cookie: JSESSIONID=…; WMONID=…` 를 붙인다.
   응답 `Set-Cookie` 로 `JSESSIONID` 가 바뀌면 저장값을 바꾼다. 상세는 지금 쿠키 없이도 되지만 같은 규칙으로 보낸다(서버가 언제든 바꿀 수 있다).
3. 업데이트 이행: 토큰은 있는데 저장된 `JSESSIONID` 가 없는 기기(2.5.1 이하에서 올라온 모든 사용자)는 첫 공식 API 요청 전에 저장된 계정으로 **자동 재로그인**해 세션을 확보한다(사용자 조작 없이).
4. 401 처리: 재로그인(새 토큰+새 `JSESSIONID`) 뒤 한 번 재시도. 재시도도 401 이면 "만료"가 아니라 별도 오류(예: `official_session_rejected`)로 기록하고, 화면 문구는 "안전신문고가 로그인을 받아 주지 않습니다. 잠시 뒤 다시 시도해 주세요." 처럼 사실대로(쉬운 말, 내부 용어 금지).
   기기 로그에는 HTTP 상태·재시도 결과·응답 형식만 남기고 **토큰·쿠키·비밀번호는 절대 남기지 않는다**.
5. 포그라운드·백그라운드 isolate(WorkManager)·알림 엔진 모두 같은 저장소에서 읽어 같은 규칙으로 동작한다.
6. 로그아웃·계정 변경·모드 전환 때 저장된 쿠키도 함께 지운다.

### 시험
모의 HTTP(실제 요청 형식을 검사하는 가짜 서버/클라이언트)로: 쿠키 없으면 401·있으면 200, 로그인 응답 쿠키 저장, `Set-Cookie` 갱신 반영, 업데이트 이행(쿠키 없는 저장 토큰 → 자동 재로그인 → 성공),
재시도도 401 → 새 오류, 로그·화면에 비밀값 없음, 로그아웃 시 삭제, 백그라운드 경로. 기존 로그인 시험은 로그인 함수를 통째로 바꿔치기하므로 요청 형식(헤더·쿠키)을 직접 검사하는 시험을 새로 둔다.

## C. 이슈 11번 — 신고내역 카드 목록 정렬

요청(사용자, 2026-10-23): 신고내역 화면의 카드 목록에서 정렬 기준과 오름차순/내림차순을 고를 수 있게 한다. 이슈 작성자는 특히 "불수용 신고를 답변일자로 정렬해서 보고 싶다"고 했다.

1. 정렬 기준 7개, **순서는 상세 검색창(`lib/widgets/search_filter_sheet.dart`) 화면에 보이는 순서 그대로**(사용자 결정):
   신고번호 → 과태료/범칙금 → 별점 → 보완횟수 → 신고일 → 발생일 → 답변일. 표시 이름도 상세 검색창과 같은 말을 쓴다.
2. 배치: 사람이 목록을 보다가 바로 찾고 한 손으로 누를 수 있는 곳 — 카드 목록 바로 위(결과 건수 줄 옆 등)에 지금 기준과 방향이 한눈에 보이는 작은 버튼(예: "신고일 ↓")을 두고,
   누르면 기준 7개를 고르는 시트를 연다. 방향은 같은 기준을 다시 누르거나 별도 ↑/↓ 토글로 바꾼다. 화면이 좁은 기기(360dp)와 큰 글씨 설정에서도 잘리지 않게.
   지금 화면 구조(검색·필터 버튼, 탭, 상단 바)를 먼저 읽고 기존 컴포넌트·디자인 토큰을 써서 어울리게 한다. 판단 근거를 보고서에 쓴다.
3. 값이 없는 신고(답변일 없음, 과태료 없음, 별점 없음 등)는 방향과 관계없이 **맨 뒤**. 같은 값끼리는 지금 기본 정렬 순서를 둘째 기준으로 써서 순서가 흔들리지 않게.
4. 기본값은 지금 화면의 정렬과 같게(업데이트 뒤 목록 모양이 갑자기 바뀌지 않게). 고른 정렬은 기기에 기억(모드·탭별로 필요하면).
   검색·필터·탭과 함께 동작하고, 정렬을 바꾸면 목록 맨 위로 이동한다. 페이지 나눠 불러오기를 쓰면 정렬은 DB 쿼리에서 해야 한다(앞 페이지만 정렬되지 않게).
5. 큰 목록(5만 건 시험 자료)에서도 느려지지 않게 필요한 인덱스·쿼리 확인.
6. 문구: 쉬운 말, 느낌표·이모지 없음. 접근성 라벨("정렬: 신고일, 최신순" 같은 읽기 문구).
7. 시험: 기준 7개 × 방향 2개 정렬 결과, 값 없는 신고 맨 뒤, 같은 값 순서 고정, 기본값 = 기존 정렬, 기억/복원, 필터와 함께, 위젯 시험(버튼 표시·시트·선택). 5만 건 성능 시험이 있으면 정렬 기준별로 예산 안인지.
8. `docs/releases/unreleased.md` 달라진 점에 한 줄: "신고내역을 신고번호·과태료·별점·보완횟수·신고일·발생일·답변일로 정렬하고, 오름차순과 내림차순을 고를 수 있습니다."
9. **중복차량 탭**(사용자 추가 지시 2026-10-23, 이슈 11번 2항): 중복차량 탭의 정렬 기준에는 **'중복횟수'**(같은 차량이 신고된 횟수, 카드에 이미 표시되는 값)를 더한다.
   위치는 7개 기준 목록의 **맨 앞**(이 탭에서 가장 많이 쓸 기준)으로 두고, 이 탭의 기본 정렬은 지금 화면과 같게 유지한다. 같은 버튼·시트 구성을 쓴다.
   중복횟수 내림차순 = 가장 많이 걸린 차량이 위. 같은 횟수는 지금 기본 순서로. 시험에 포함.
10. **중복차량 탭은 차량번호 묶음 단위로 정렬한다**(사용자 지시 2026-10-23): 이 탭은 같은 차량번호의 신고들이 한 묶음(그룹)으로 보인다. 어떤 기준으로 정렬하든
    **묶음 전체가 함께 움직이고, 묶음이 쪼개지거나 다른 차량 신고와 섞이면 안 된다.**
    - 묶음의 순서 = 그 기준의 묶음 대표값으로 정한다: 중복횟수는 묶음 크기, 날짜·신고번호는 내림차순이면 묶음 안 최댓값·오름차순이면 최솟값,
      과태료·별점·보완횟수도 같은 방식(내림차순=묶음 최댓값, 오름차순=묶음 최솟값). 값이 하나도 없는 묶음은 맨 뒤. 대표값이 같으면 지금 기본 묶음 순서로.
    - 묶음 안의 카드 순서는 같은 기준·같은 방향으로 정렬하되, 값 없는 카드는 묶음 안에서 맨 뒤.
    - 페이지 나눠 불러오기를 쓰면 묶음 단위로 끊어 앞 페이지에 묶음 일부만 오지 않게(지금 묶음 페이징 규칙 확인).
    - 시험: 기준·방향마다 묶음이 쪼개지지 않음, 묶음 대표값 순서, 묶음 안 순서, 값 없는 묶음 맨 뒤.
